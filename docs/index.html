The buttons open the latest release. Not sure which Mac you have? Apple menu > About This Mac: a chip named M1 or later is Apple silicon.

The installers are not signed with a paid certificate, so the first launch has to be allowed by hand:

  • Windows: SmartScreen shows a warning. Choose More info, then Run anyway.
  • macOS: right-click the app and choose Open, or allow it in System Settings > Privacy & Security > Open Anyway.

Virtual machines need QEMU: winget install SoftwareFreedomConservancy.QEMU on Windows, brew install qemu on a Mac. Without it the app still opens and remote desktop works.

Use

Every computer runs the same app.

  1. On the computer you want to reach, open Remote desktop, go to This computer and tick Allow remote connections. It shows an address and an access code.
  2. On the one you're sitting at, open Remote desktop, type both and press Connect.
  3. Back on the first computer a question pops up: allow or deny.

A Mac that is going to be used from another computer needs two permissions, Screen Recording and Accessibility. Both have a button on Remote desktop > This computer.

The protocol

Remote desktop runs on ARDP, a protocol written for this project and specified in full in PROTOCOL.md.

transportone TCP connection, port 7389, always inside TLS 1.2 or newer
handshakeboth sides prove the access code with scrypt and HMAC-SHA256, bound to the certificate and to the TLS session
pictureH.264 (VP8 or VP9 as fallbacks), sent only when the screen changes
inputphysical keys and 0 to 1 pointer coordinates

Everything is encrypted, on a LAN as well as across the internet. The access code is never sent, and by default someone at the computer has to allow each connection. There is no relay: reaching a computer from outside your network means forwarding a port or using a VPN. Nobody outside the project has audited it. The full list is in the security model.
